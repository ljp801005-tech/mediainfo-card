## v1.10.3

修「页面上出现两份媒体信息」。SpringSunday details.php?id=631687 的简介行里有两样东西：站点自己渲染的可见面板（文件名 / 体积 / 时长 / 分辨率 / 视频 / 音频 / 字幕），和一段隐藏的 MediaInfo 原文。脚本只收起原文，那份可见面板还挂在那儿，卡片下面又列一遍同样的信息。

现在收起原文时顺手把同源的站点面板一起收起：按文件名认亲（去空白后完整匹配，文件名太短不认），要求至少命中 3 个 MediaInfo 字段（体积 / 时长 / 分辨率 / 视频 / 音频 / 字幕 / Format 等），并且只在这份信息所在的简介行 / 简介格子里找，不碰发布信息表；夹着截图或视频的容器不动，含卡片的容器也不动。面板外面带标题的外壳（MediaInfo / 媒体信息）一起收，不留空标题条；这一行除了面板只剩标签时整行收掉。切悬浮、收起卡片仍全部还原，诊断的「原文替换」一行会写明「另收起站点自带面板 N 处」。

## v1.10.2

修「字幕全 —，要切到 2/2 才看得到」。Audiences details.php?id=744865 实测：页面上同一份 MediaInfo 出现两次 —— 简介里是 ptgen 面板（General / Video / Audio 三栏，字幕整栏没有），另有一块上传者贴的原文（6 条字幕齐全）。两者各自被认成候选，卡片默认落在面板那份上，于是字幕全空、音频还带出「English JOC」「E-AC-3 (English)」这类面板特有的粘连；点「›」切到第二份才有字幕。

现在按文件名把同源候选合成一份：媒体字段更全的当底，另一份只补空项与更长的列表；锚点仍取面板那份，落位方式与「收起原文」的范围不变。实在只有一个候选、而面板又没有字幕栏时，再从整页文本里找「同名」的那段 MediaInfo 补字幕（必须文件名一致，宁缺勿错）。诊断新增「同源合并」「字幕来源」两行。

顺带修音频编码映射：`mapFmt` 原来按表里的顺序取第一个「包含」的键，`E-AC-3 JOC` 会先命中中间的 `ac-3`，卡片上把 DD+ Atmos 写成 DD；现在改成「最靠前 + 最长」的键，并补上 Atmos 几个写法（`E-AC-3 JOC` → DD+ Atmos、`AC-3` → DD、`DTS-HD Master Audio` → DTS-HD MA 不再被 `DTS` 抢走）。

## v1.10.0

修「多栏 HTML 面板只认出体积、其余全是 —」（Audiences 一类模板）：这类模板把 MediaInfo 摊成「表头行 + 一行多个内容格」，整块读出来是 General / Video / Audio / Subtitles / Format: Matroska / Duration: …几个段头全挤在开头，段头与内容对不上，字段全落进同一段 —— 卡片就成了「视频 Video、音频 Matroska @ 9808 Kbps、时长/帧率/分辨率/字幕全 —」。① 新增多栏面板重建：识别「表头行全是栏名」的表格（th 或 td、一行或多行内容），以及「标签条 + 各栏内容」的 div 结构，按栏把内容重新对齐；② 单元格内 <br> / 块级元素都当换行；「Format:」与「Matroska」被拆两行也能接上；③ 无标签的轨道行按紧凑写法解析：English E-AC-3 2.0ch @ 224kb/s → 语言/编码/声道/码率，字幕栏 English UTF-8 (British) 同理；④ General 栏的 Bit Rate 记成总体码率，不再被当成视频码率；⑤ 标签表补上 Format / Container，之前面板里的 Format 行整条被丢弃；⑥ 修 fileName 被「File size」骗走（pick 的前缀匹配会用 'File' 命中 'File size'），文件名不再显示成 6.44 GiB；⑦ 面板藏在 display:none 里、整页读不到正文时，也能靠重建结果出卡片

## v1.9.8

修「正文底色由背景图画出来的站点判错深浅」（FileList 官方 blue 皮肤实测）：该站 body 是浅灰 #b3b4ab，正文区 .cblock-content 的深色是 content-bg-blue.png 画的，整条祖先链上没有一处纯色底。旧逻辑量不出纯色底时会退到 body / html 的纯色底，于是把深色正文判成浅色主题 —— 字段值 #26303f 压在深色正文上，只有标签看得见。① 祖先链在遇到 background-image 时立即止步，不再往上取 body 的浅色；整页采样也去掉了「退到 body 纯色底」这一步；② 量不出纯色底时改用「同一位置站点自己的文字色」推断深浅：这一块的字是浅色就说明底是深的（FileList 正文色 #E0E0E0 → 深色主题）；③ 站点采样配色按「本地结论」校验：深色块里采到深色字就整组丢弃；④ 诊断「配色」一行会写明「卡片背后是背景图，按同位置文字色推断」

## v1.9.7

再修「主题选自动时字段看不见」（手动亮色 / 暗色已正常）：① 深浅判定不再做「整页取点投票」，改为只量卡片自己那块地方：用 elementsFromPoint 取卡片矩形里 9 个点、跳过卡片自身，逐层找第一个不透明背景，按亮度分桶取多数票。深色详情页里常夹着大块浅色区域（海报 / iframe / 白底说明面板 / 侧栏），整页投票常常被它们带偏，判成浅色主题 → 深色字段值压在深色页面上，看着像空的；② 对比度校正的底色来源改成「卡片正后方实测 → 卡片祖先链 → 整页投票 → 文字色反推」四级降级，实测优先，不再让整页投票抢在实测前面；③ 站点采样的配色要先跟「卡片后方实测底色」对一次，对不上就整组丢弃改走主题默认色；④ 手动选了亮色 / 暗色时，本地实测底色只用于校验配色，绝不顶掉用户的选择；⑤ 诊断「配色」一行的页面底会标注「卡片后方实测」，一眼看出这个数是量出来的还是猜的

## v1.9.6

修「主题开关按了没用 / 深色站点上切亮色整块变空白」：① 手动选了亮色 / 暗色时，站点配色不再覆盖它（原来采样直接把 --mi-fg 和深浅类改回去，等于开关失效）；手动主题下透明卡片读不出来时改为给卡片自己上底色（白底深字 / 深底浅字）；② 深浅判定改为实测页面主体底色（在页面上取几个点、逐层找背景色投票，避开卡片自身），不再只信 body 文字色 —— 深色皮肤常常「底色在 html / 背景图上、body 还是黑字」，旧逻辑会把深色页面判成浅色；③ 对比度校验改为逐字段实测（跳过「—」占位），任一字段看不清就校正；④ 字段名 / 字段值的颜色选择器带上 .mi-root 前缀，压过站点的 td 级 color 规则；⑤ 诊断「配色」一行补上主题、文字色、页面底、亮度差、是否自带底色

## v1.9.5
