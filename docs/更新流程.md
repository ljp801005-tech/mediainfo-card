# 更新流程

仓库：<https://github.com/ljp801005-tech/mediainfo-card>
唯一维护源：`mediainfo-card.user.js`（`scripts/` 只是构建辅助，不改功能）

## 一、改脚本

1. 编辑 `mediainfo-card.user.js`；
2. **递增 `// @version`**（如 `1.8.0` → `1.8.1`）——油猴只认这一行判断有没有新版；
3. 在 `docs/CHANGELOG.md` 顶部加一节 `## v1.8.1`（写清改了什么、为什么这么改，这是完整历史）；
4. `RELEASE_NOTES` 里**只保留一条**汇总（卡片「关于」面板显示的就是它，不铺历史），把 `v` 和 `d` 换成这次的内容——一两句、说清「这版对用户意味着什么」即可，别写成变更清单；
5. 本地自检：

```bash
node --check mediainfo-card.user.js
node scripts/build-gf.mjs        # 顺带确认 GF 版能正常剥离 updateURL
```

6. 提交并推送：

```bash
git add -A
git commit -m "fix: 一句话说明"
git push
```

推送后约 1 分钟，`https://raw.githubusercontent.com/ljp801005-tech/mediainfo-card/main/mediainfo-card.user.js`
就会是新内容（CDN 缓存通常几分钟内刷新）。用户侧：Tampermonkey 默认 24 小时检查一次，也可手动「检查脚本更新」或点油猴菜单里的「检查更新」。

## 一·五、加一个站点（常见需求）

脚本按「站点登记表 + 三级落位」工作，加站点只动三处：

1. 头部元数据补两行 `@match`（裸域 + `*.域`，两个都写，别省）：

```js
// @match  *://example.com/*
// @match  *://*.example.com/*
```

2. 在 `SITES` 里登记一行，`name` 会显示在诊断与「关于」面板：

```js
{ host: 'example.com', name: 'Example', kind: 'nexus' },
```

> 对外清单有例外：`SITES` 里有一站按站方要求**不点名**（那行上方有注释），`@match` 与登记照旧保留即可，别再往 README / Greasy Fork 附加信息 / 发帖说明的站点清单里补。改文档时清单按「点名 N 个 + 1 个不点名」写，总数照旧。

3. 结构特殊（没有 `table` 行、或认不出「简介」类名）时，给该行补 `desc` 线索，
   卡片就能落在简介区块前，而不是退回右下角悬浮：

```js
{ host: 'example.com', name: 'Example', kind: 'custom',
  desc: ['.markdown-body', '.panel-body', '[class*="description"]'] },
```

发种 / 编辑页要排除的话，`excludePaths` / `excludeQueries` 里补一条即可。

改完先跑一次自检，它会检查「登记表 ↔ @match 是否一一对应」，漏写会直接失败：

```bash
node tests/sites.test.cjs
```

CI 里也有同样一步，push 后 Actions 会再跑一遍。

## 二、打 tag（可选，留档 + Release 附件）

```bash
git tag v1.8.1 && git push origin v1.8.1
```

`.github/workflows/release.yml` 会：
- 校验 `@version` 与 tag 一致（不一致直接失败）；
- `node --check`；
- 生成 `dist/mediainfo-card.gf.user.js`；
- 创建 Release，把两个 `.user.js` 挂到附件。

固定下载地址（永远指向最新 Release）：
`https://github.com/ljp801005-tech/mediainfo-card/releases/latest/download/mediainfo-card.user.js`

## 三、同步到 Greasy Fork（可选）

GF 会在发布时写入它自己的 `@updateURL` / `@downloadURL`，所以**不要直接把主文件贴过去**，
先用构建脚本生成剥离版：

```bash
node scripts/build-gf.mjs
# 产物：dist/mediainfo-card.gf.user.js
```

然后 GF 脚本页 →「管理」→ 新建版本 → 粘贴 `dist/mediainfo-card.gf.user.js` 的内容，
版本号与 `@version` 一致；附加信息用 `docs/greasyfork-附加信息.md`，更新说明写本次改动。

发布后核对线上文件：

```bash
curl -sL -H 'Referer: https://greasyfork.org/' \
  https://update.greasyfork.org/scripts/605024/mediainfo-card.user.js \
  -o /tmp/gf-online.js
node --check /tmp/gf-online.js
```

与 `dist/mediainfo-card.gf.user.js` 相比，只应差 GF 注入的 `@updateURL` / `@downloadURL` 两行。

> 注意：`update.greasyfork.org` 与 `raw.githubusercontent.com` 都有 CDN 缓存，刚发布就拉可能还是旧文件，
> 等几分钟或换 `curl` 直连（浏览器上下文里可能命中另一份缓存）。

## 四、两条渠道的关系

| 安装来源 | 更新来源 | 元数据里的更新地址 |
| --- | --- | --- |
| GitHub Raw | 本仓库 `main` | 脚本自带的 `@updateURL`（raw） |
| Greasy Fork | Greasy Fork | GF 注入的 `@updateURL` |

两者内容一致、互不干扰。已经装了 GF 版想切到 GitHub 版：点一次 GitHub 的 Raw 链接覆盖安装即可，
此后由本仓库推送更新。

## 五、版本号约定

- `X.Y.Z` 三段数字，只用递增，不回退；
- 修 bug 升 Z，加功能升 Y，改架构或大改版升 X；
- tag 名带 `v` 前缀（`v1.8.1`），脚本里不带（`1.8.1`），CI 会校验两者一致。
